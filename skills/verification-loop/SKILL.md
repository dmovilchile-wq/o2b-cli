---
name: verification-loop
description: Never declare a change done without running the tests/commands that prove it. Use at the end of any implementation task, before reporting completion.
origin: O2B-CONTRIBUTOR
version: 1.0.0
tags: [contributor, engineering-practice]
---

Before saying a task is complete: run the relevant tests or commands and
show their real output. If something could not be verified, say so
explicitly as "NOT VERIFIED" and why, instead of asserting success.
